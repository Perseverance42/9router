# RouteWeave backend opt-in (experimental v1)

Disabled unless the requested combo is named in `ROUTEWEAVE_COMBOS`. No UI/settings fields. Configure only the server environment:

```sh
ROUTEWEAVE_COMBOS=text-combo
ROUTEWEAVE_MODE=active_required
ROUTEWEAVE_URL=http://127.0.0.1:9090
ROUTEWEAVE_DECISION_TIMEOUT_MS=35000
ROUTEWEAVE_SERVICE_TOKEN=<integration-service-token>
ROUTEWEAVE_ALLOWLIST='{"openai/gpt-example":{"text":true,"context_tokens":32768,"max_output_tokens":4096,"tokens_per_byte":1,"template_tokens":1024}}'
```

The example model is a placeholder, not verified metadata. Each allowlist entry is an operator assertion for an exact gateway execution route. `tokens_per_byte` must upper-bound its tokenizer over the UTF-8 serialized request, and `template_tokens` must cover translation/template/provider overhead. No inferred capability/context defaults. Unknown models are excluded; invalid entries or an empty eligible pool fail before dispatch. Requests must explicitly supply positive `max_tokens`, which is reserved and passed unchanged to dispatch. `max_completion_tokens` alone is rejected; when supplied alongside `max_tokens`, it must match exactly. Enable only after certifying these bounds and that translation/providers honor output limits.

Only flat, concrete-model combos and text-only OpenAI chat/Claude messages are supported. The exact execution ceiling is canonical resolved providers `openai` and `anthropic`, using their registry `DefaultExecutor` and upstream `openai` chat or `claude` format. All other providers/custom nodes/executors, including canonical `codex` and aliases resolving to it, are rejected before a decision. Responses target formats are rejected again in chat core after final transport/model-format resolution and before upstream dispatch; this also covers a registry model-format override. Client format alone does not establish eligibility. These exclusions are code-enforced, not operator-certifiable exceptions. Thinking suffixes are rejected on candidate IDs, resolved models and upstream model IDs. Developer messages are rejected whenever the eligible pool contains a Claude target, because the current translator drops that role; OpenAI-only pools preserve it. Roles are `system`, `developer`, `user`, and `assistant`; the transcript must end with a nonempty user message (at most 128 user messages). No tools (even empty declarations), media, Responses API inputs, continuity, cache-control blocks, unknown request extensions, multiple generations, nested combos or fusion. Request transforms and provider thinking overrides must be disabled so admission/classification describe what is dispatched. Unsupported opted-in requests return 422 in **all modes**, not unrestricted native fallback. Non-opted-in traffic is unchanged. Naming/warmup bypass is disabled for opted-in combos.

- `shadow`: bounded decision wait, then native routing over the **hard-admitted pool**. Native smart classification may still run because this mode preserves native routing. Outcomes identify the native serving route, not the recommendation.
- `active_advisory`: valid external order; on sidecar failure use original hard-admitted order. No native smart classifier, stickiness, rotation, capability reorder or capacity-adapter additions.
- `active_required`: invalid/unavailable decisions fail 503 before completion dispatch. External order and the same hard admission apply to every fallback. Expiry is rechecked before account/credential refresh attempts and immediately before every executor/proxy fetch, including retries. Retry waits are abortable; an already-started valid upstream response may finish after decision expiry.

A decision call has a 35-second default total fetch/body deadline (`ROUTEWEAVE_DECISION_TIMEOUT_MS`, integer 100–60000 ms), no retries, one UUID request ID, a UUID candidate snapshot and a 256 KiB body limit. Feedback retains its independent fixed 1-second timeout. At most 32 candidates and 256 messages. Response validation requires request/mode/snapshot binding, nonempty decision/policy IDs, `status: ranked`, finite scores, a complete unique candidate permutation and an expiry within the next 60 seconds. Wire fields follow `routeweave/docs/decision-api.md`; pin to executable service fixtures before deployment.

Sidecar requests contain only the dedicated service token, normalized transcript, hints, admission requirements and candidate IDs. They never receive client authorization, provider credentials, session identity or arbitrary client-selected URL. Use HTTPS outside a trusted local transport. HTTP redirects are rejected.

Outcomes are bounded best-effort (32 concurrent deliveries, 1-second timeout, no retries/persistence); delivery failure does not fail completion. A bounded reader inspects upstream bytes before translation; a private response WeakMap carries mutable per-attempt evidence through chat core and combo peeking to the downstream observer. Neither reader tees or retains an unbounded response copy. JSON bodies and SSE buffered for non-streaming clients are cancelled and rejected above 256 KiB before translation can accumulate the full body. Success requires usable delivered text and genuine upstream terminal evidence, not translator-generated markers. Upstream streams require usable text, a genuine OpenAI `finish_reason` (`stop`/`length`) plus `[DONE]`, or Claude `message_delta.stop_reason` (`end_turn`/`max_tokens`/`stop_sequence`) plus `message_stop`, and clean EOF. A synthetic `[DONE]`, EOF, or HTTP 200 alone is failure. Cancellation/errors are terminal failures/cancellations. JSON success requires parsed usable text, a recognized successful finish/stop reason, and no error envelope, both before and after translation. Opted-in JSON empty/error200/unfinished results become retryable failures. Explicit refusal/content-filter responses retain no-retry behavior and report failure rather than a successful served route; native tools retain native handling. Opted-in pre-content SSE peeking is capped at 256 KiB. Streaming failover remains bounded by native prefix peeking: once text is committed, a late upstream error reports failure without replaying another model. Attempts describe model-route dispatches, not individual account retries; account identities/errors are never reported. Every failed attempt includes a finite backend category (`transport_failure`, `rate_limit`, `incompatibility`, `empty_generation`, `temporarily_unavailable`, `timeout`, or `provider_error`); succeeded/cancelled attempts omit category. All-failed native shadow responses report every attempted route as failed, without inventing a serving route.

`/v1/systemone` now has a 15-second endpoint budget across account fallback and propagates request cancellation/deadline into provider fetch/body consumption. Existing credential refresh/DB work is not abortable; endpoint response is bounded, but already-running local work may finish before observing cancellation. Opted-in expiring decisions fail closed on the unverified manual DNS-bypass transport; ordinary TLS/proxy fetch retries recheck expiry before starting.

Opted-in chat forwards request cancellation through account-attempt boundaries and combines it with the native stream-controller signal used by executors. Cancellation stops later model/account attempts; the observer cancels the downstream reader to trigger upstream teardown. Nonabortable credential/DB work may finish before checking the signal; executor cancellation still depends on providers honoring fetch abort. Base executor retry waits now honor cancellation for native traffic too; native routing and response-content rules are unchanged. Account-level attempt aggregation and durable feedback are not implemented. No runtime provider verification was performed.
